Server Signing

HMAC signature on your server

The HMAC key never reaches the browser. The page sets server.sign, which sends each message to sign (the WebSocket challenge, or an HTTP request body) to a server that holds the key.

Start the signing server first: node --env-file=.env.local examples/server-signing/server.js. It reads APPLICATION_KEY, HMAC_KEY, HOST and SCHEME.
The page fetches the public part of the configuration (host, application key) from the same server, so it holds no credential at all.
In production, put /sign behind your own authentication and rate-limit it.

The signing server does not answer

This page holds no credential: it asks a local server for the configuration and for every signature. Start it:

  1. At the root of the repository, put your keys in .env.local: 
    APPLICATION_KEY=<your application key>
HMAC_KEY=<your HMAC key>
HOST=cloud.myscript.com
SCHEME=https
  2. Start the signing server, and leave it running: 
    node --env-file=.env.local examples/server-signing/server.js
  3. Open this page from http://localhost:8000: the server only answers that origin (set ALLOWED_ORIGIN to change it).
