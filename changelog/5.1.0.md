# v5.1.0 — details

Full record of every change in [v5.1.0](../CHANGELOG.md#v510). The one-line summary of each change is in [CHANGELOG.md](../CHANGELOG.md); step-by-step upgrade instructions are in [MIGRATION.md](../MIGRATION.md).

## Features

### Save and resume a session: `.iinkts`
`canvas.session` saves what is needed to resume the work later, even once the server session has expired (about one hour without activity): the symbols and, from server 4.6.0, the server session as a `.iink` package (see below).
- `canvas.session.save()` resolves with a `TSessionEnvelope`; `canvas.exportAs("session")` gives it as a JSON `Blob`, `canvas.download("session")` as a `.iinkts` file
- `canvas.session.restore(source)` takes a `.iinkts` file (`Blob`), its text or an envelope. It replaces the content, empties the history and keeps the canvas read-only meanwhile. It resolves with `"imported"` when the server session came from the package, `"replayed"` when a new session was opened and the strokes sent again: no package in the file, server older than 4.6.0, or package refused. A source that is not a session rejects and leaves the content as it was
- the server session is resumed with the canvas configuration, not the one it was saved with
- symbols keep the dates they were saved with (`creationTime`, `modificationDate`)
- new: `IISessionManager`, `TSessionEnvelope`, `TSessionRestoreMode`, `createSessionEnvelope`, `serializeSession`, `parseSession`, `readBlobAsText`, `WebSocketClient.partId`
- **type**: `TExportFormat` and `TDownloadFormat` gain `"session"`, `TExportResultMap` gains `session: Blob` — an exhaustive `switch` over them needs the new case
- `clearOperation(label)` is now public on the canvas (it was `protected`), so a manager can end an operation no server event will end

### Session package: export and import
The server can hand over the whole session as a `.iink` package, and start a new session from one. This is the ground for resuming work after the server session has expired.
- `WebSocketClient.exportPackage()` resolves with the package bytes. The server waits for the recognition to be idle first. Calls run one after another; it resolves with `undefined` when the session is closed deliberately meanwhile, and rejects when the received bytes do not add up to the announced size
- `WebSocketClient.importPackage(bytes, partId)` replaces the session with one started from the package, on a new connection, and opens `partId`. Stroke ids are kept, and a later reconnection restores the imported session. It rejects when the server refuses the package — through the rejection only, not the client's `error` event, as the caller may recover from it; the next connection then starts a new session
- both need server 4.6.0 or later and reject on an older one: `supportsSessionPackage(serverVersion)` tells
- new: `TWebSocketClientMessagePackageInfo`, `TWebSocketClientMessagePackageChunk`, `TWebSocketClientMessageImportPackageChunkAck` and their `TWebSocketClientMessageType` members; `bytesToBase64`, `base64ToBytes`
