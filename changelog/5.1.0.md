# v5.1.0 — details

Full record of every change in [v5.1.0](../CHANGELOG.md#v510). The one-line summary of each change is in [CHANGELOG.md](../CHANGELOG.md); step-by-step upgrade instructions are in [MIGRATION.md](../MIGRATION.md).

## Features

### Save and resume a session: `.iinkts`
Try `interactive_canvas_session.html`: save and open a `.iinkts` file, the sessions saved in the browser after a reload, a second tab locked out.

`canvas.session` saves what is needed to resume the work later, even once the server session has expired (about one hour without activity): the symbols and, from server 4.6.0, the server session as a `.iink` package (see below).
- `canvas.session.save()` resolves with a `TSessionEnvelope`; `canvas.exportAs("session")` gives it as a JSON `Blob`, `canvas.download("session")` as a `.iinkts` file
- `canvas.session.restore(source)` takes a `.iinkts` file (`Blob`), its text or an envelope. It replaces the content, empties the history and keeps the canvas read-only meanwhile. It resolves with `"imported"` when the server session came from the package, `"replayed"` when a new session was opened and the strokes sent again: no package in the file, server older than 4.6.0, or package refused. A source that is not a session rejects and leaves the content as it was
- the file is named after the first three words of the recognized text (`Shopping list for.iinkts`), or after the date when nothing is recognized; `{ filename }` still names it. `canvas.session.suggestedFileName()` gives that name, the dated one included; new: `datedFileName`
- in the action menu, **Session** shows two explained sections: **Save to a file** downloads the `.iinkts` file under the name typed in its field, which suggests the first words of the document, or the dated name the file would otherwise get, and **Open a file** restores one; a message confirms the save (`Session saved: <name>.iinkts`), and tells when an opened session is recognized again rather than imported; a file that is not a session shows the error and leaves the content as it was. `menu.action.session: false` hides it. New: `SessionMenuAction`, `TMenuActionConfig.session`; a `"textinput"` menu item (`TextInputMenuItem`, `TMenuTextInput`: a field with a suggested value and a validation button), `fileNameFromText`; `"textinput"` and `"fileinput"` items take an optional heading (`TMenuFieldHeading`: `icon`, `title`, `hint`). A sub-menu now updates its items when it opens
- the server session is resumed with the canvas configuration, not the one it was saved with
- symbols keep the dates they were saved with (`creationTime`, `modificationDate`)
- the undo/redo history is saved with the session, in the file and in the browser, redo steps included: once restored, the work can be undone as before (up to `undo-redo.maxStackSize` steps). A file without history, or whose history can not be read, opens with an empty one. New: `exportStack()` / `importStack()` on the histories (`THistoryStack`), `TSessionEnvelope.history`, `parseHistory`, `parseSavedContent`
- new: `IISessionManager`, `TSessionEnvelope`, `TSessionRestoreMode`, `createSessionEnvelope`, `serializeSession`, `parseSession`, `readBlobAsText`, `WebSocketClient.partId`
- **type**: `TExportFormat` and `TDownloadFormat` gain `"session"`, `TExportResultMap` gains `session: Blob` — an exhaustive `switch` over them needs the new case
- `clearOperation(label)` is now public on the canvas (it was `protected`), so a manager can end an operation no server event will end

### Resume after reloading the page: browser storage
`canvas.session` saves the session in the browser (IndexedDB), so the work survives a reload, a closed tab or a crash.
- each page load writes its own entry under the document key, from its first change on: the symbols 500 ms after the changes pause, the snapshot (with the server package) when it is taken, and both at once when the page is hidden. An empty canvas deletes its entry. The sessions earlier pages saved are kept next to it, never overwritten
- the document key is `configuration.persistence.key`, by default the page path and the canvas element id (`/notes.html#editor`); the query and the hash are not part of it
- once initialized, `canvas.session.saved` lists the sessions earlier pages saved for the document (`TSavedSessionInfo`: dates, symbol count, size), and the `saved-sessions-available` event gives them — register it before `initialize()` to receive it. Nothing is restored on its own: `canvas.session.restoreSaved(id)` restores one (package imported, then what changed since sent; otherwise every stroke) and writes it on as this canvas's own entry; `canvas.session.discard(id?)` deletes one, or all
- one canvas at a time writes a document, across tabs: Web Locks, or a lease renewed in IndexedDB outside a secure context — released when the page goes away, taken back by a reload in the same tab. Another canvas gets `session-storage-unavailable` with `"locked"` and stores nothing; `"unsupported"` (no IndexedDB), `"lost"` (lease taken over while the page slept) and `"error"` are the other reasons
- entries not written for `persistence.maxAge` (30 days) are purged at start, then the oldest beyond `persistence.maxSize` (50 Mi characters) for all documents
- **behaviour**: on by default — `configuration.persistence.storage: false` turns it off. Content written in a canvas is now kept in the browser storage of the page's origin
- new: `TPersistenceConfiguration.storage`, `.key`, `.maxAge`, `.maxSize`; `IISessionManager.start`, `.saved`, `.restoreSaved`, `.discard`; `CanvasEventName.SAVED_SESSIONS_AVAILABLE`, `SESSION_STORAGE_UNAVAILABLE` and their `addSavedSessionsAvailableListener` / `addSessionStorageUnavailableListener`; `SessionStorage`, `SessionLock`, `SessionBrowserStore`, `TSavedSessionInfo`, `TSavedSession`, `TSessionLease`, `TSessionLockContext`, `TSessionStorageUnavailableReason`, `parseSymbols`

### Resume automatically once the server session expired
The server drops a session after about an hour without activity. Reconnecting then used to report `restore.session.not.found` as an error and open an empty session, the canvas keeping ink the server no longer knew. Now:
- `canvas.session` keeps the session in memory (symbols and `.iink` package) `configuration.persistence.snapshotDelay` ms after the last change (default 5000, `0` never), and at once when the page is hidden. Not while offline, nor on a server older than 4.6.0
- once the server has lost the session, the client starts the new one from that package and the canvas sends only what changed since (strokes added, erased, or changed in place); without a package, or when it is refused, a new session gets every stroke. No error is reported; the changes queued while disconnected are dropped, as the resync covers them, and the requests waiting for the reconnection go once it is done
- the history is kept
- **behaviour**: `configuration.server.serverSideRecovery` is `false` by default (server 4.6.0+): the server no longer saves the session (no server autosave, no `restoreSession`), the client snapshots are the only way back. After a drop, the client never asks `restoreSession`: it starts a new session from the last snapshot, then sends what changed since; without `canvas.session` (a bare `WebSocketClient` without `setSessionRecovery`), an empty session, and the loss is reported. `true` gives the server recovery back and sends the messages as before, without the field, to a server that does not know it. New: `TServerWebsocketConfiguration.serverSideRecovery`
- new: `TPersistenceConfiguration`, `DefaultPersistenceConfiguration`, `configuration.persistence`; on the client, `TSessionRecovery` and `WebSocketClient.setSessionRecovery(recovery)` — without one, the client behaves as before

### Session package: export and import
The server can hand over the whole session as a `.iink` package, and start a new session from one. This is the ground for resuming work after the server session has expired.
- `WebSocketClient.exportPackage()` resolves with the package bytes. The server waits for the recognition to be idle first. Calls run one after another; it resolves with `undefined` when the session is closed deliberately meanwhile, and rejects when the received bytes do not add up to the announced size
- `WebSocketClient.importPackage(bytes, partId)` replaces the session with one started from the package, on a new connection, and opens `partId`. Stroke ids are kept, and a later reconnection restores the imported session. It rejects when the server refuses the package — through the rejection only, not the client's `error` event, as the caller may recover from it; the next connection then starts a new session
- both need server 4.6.0 or later and reject on an older one: `supportsSessionPackage(serverVersion)` tells. A server announcing 4.6.0 without the feature answers `exportPackage` as an unknown message: the error event then says the server cannot save the session (`ClientError.SESSION_PACKAGE_UNSUPPORTED`), and `WebSocketClient.sessionPackageSupported` turns false so it is not asked again — the session is then saved without package and resumed by sending the strokes again. An empty canvas is not saved in memory
- new: `TWebSocketClientMessagePackageInfo`, `TWebSocketClientMessagePackageChunk`, `TWebSocketClientMessageImportPackageChunkAck` and their `TWebSocketClientMessageType` members; `bytesToBase64`, `base64ToBytes`

### Lock symbols (INTERACTIVE_INK)
A locked symbol stays selectable, copyable and exportable, and is still recognized, but nothing changes it: no move, resize, rotation, erase, scratch/join/insert gesture, conversion, restyle or reorder, whether the user or the API asks. Meant for fixed content an integrator lays down, such as an exercise statement or a diagram background.
- new: `TBaseSymbol.locked`, `canvas.lockSymbols(ids, addToHistory?)` and `canvas.unlockSymbols(ids, addToHistory?)`. Locking is one undo step
- `updateSymbols`, `removeSymbol(s)`, `replaceSymbols` and `changeOrderSymbols` skip locked symbols and report them; a replacement touching a locked symbol is refused whole. In a mixed selection, the unlocked symbols are still changed
- **`clear()` keeps locked symbols**: it erases the others one by one instead of resetting the server
- a conversion block holding a locked stroke is left unconverted; a connected edge that is locked no longer follows its shape; decorating a locked text is refused, while decorating a locked stroke still works (the decorator is a symbol of its own)
- undo/redo replay history as recorded and ignore the lock: add content the user must not undo away with `addToHistory = false` before locking it
- new event `CanvasEventName.LOCKED_REFUSED` (`event.addLockedRefusedListener`), detail = the locked symbols a change skipped
- rendering: a locked symbol's element carries the `ms-locked` class, toned down through `--ms-ink-locked-opacity` (default `0.55`; set it to `1` to show locked symbols as any other). A fully locked selection shows a dashed frame with a padlock and no handle; a refused change flashes a padlock at the centre of the symbols (`SVGRenderer.flashLockIcon`)
- menu: context entry Lock / Unlock, `menu.context.lock` (default `true`); set it to `false` to keep locking to the API
- new: `LockContextMenu`, `createLockIcon`, `LOCK_ICON_SIZE`, `SvgElementRole.Lock`, `SVGRendererConst.lockedClassName` / `lockIconClassName` / `lockIconFlashClassName` / `lockIconFlashDuration`

### Search in recognized content (INTERACTIVE_INK)
Ctrl+F on handwriting: find a word or an expression in the recognized text and math, handwritten or converted, highlight the matched characters and bring an occurrence into view.
- new: `canvas.search` (`IISearchManager`): `find(query)` → `TSearchMatch[]` (`text`, `context`, `kind`, `source`, `symbolIds`, `boxes`, `bounds`), `highlight(matches, active?)`, `clear()`, `reveal(match)`, `highlighted`, `available` (false until something is recognized or converted)
- matching: case- and accent-insensitive, partial, literal; in text any whitespace run matches one space (phrases span line breaks); math compares without spaces in reading order (`3x+2`, `f'(x)`), inline math inside a text is read in place; exponents read linearly (`x2` finds `x²`)
- the highlight follows the last query as the content changes (erase, move, convert); a converted block is found once, as typeset
- menu: search bar `canvas.menu.search` (`IIMenuSearch`: `open()`, `close()`, `isOpen`), layout occupant `search`, stacked under the action bar by default (`"top-left": ["action", "search"]`) and folded while closed: query, `x/n` count, previous / next (Enter / Shift+Enter), Escape closes and clears the highlight; Ctrl+F (Cmd+F) opens it instead of the browser's find. `menu.search.enable` (default `true`), `menu.search.shortcut` (default `true`; set it to `false` to leave Ctrl+F to the browser), type `TMenuSearchConfig`. While nothing is recognized, the bar carries the `unavailable` class and its placeholder reads "Nothing recognized yet"
- menu: search button (magnifier) in the action bar opens and closes the search bar, for tablets and other devices without Ctrl+F; `menu.action.search` (default `true`, shown only when `menu.search.enable`), `SearchMenuAction`
- rendering: rects with `ms-search-highlight` / `ms-search-highlight-active`, colors `--ms-ink-search-highlight` (default `#ffd54f`) and `--ms-ink-search-highlight-active` (default `#ff9800`)
- new: `IIJiixQueryManager.getElements()`, `strokeIdsFromJIIXItems`, `LoggerCategory.SEARCH`, types `TSearchMatch`, `TSearchKind`, `TSearchSource`, `TSearchUnit`, `TSearchUnitChar`
- example: `interactive_canvas_search.html`

### UI translations (INTERACTIVE_INK, INK_V2)
Every label of the UI (menus, search bar, connection badge, info/error messages and the `ClientError` messages they show, PDF export dialog, math dialogs) is shown in the recognition language. English and French are built in; any other language falls back to English until the integrator supplies it.
- new: `canvas.i18n` (`Translator`): `t(key, params?)`, `language`, `setLanguage(lang)`, `add(lang, labels)`, `onChange(listener)`. A label is looked up in `fr_FR`, then `fr`, then `en`, the integrator's labels over the built-in ones at each level; an unknown key is shown as is
- new: `configuration.translations` (`TTranslationsConfiguration`), labels by language code (`fr` or `fr_FR`), to override built-in labels or add labels of one's own: `{ fr: { "menu.action.clear": "Tout effacer" } }`
- the UI follows `recognition.lang` at load and after `updateRecognitionConfiguration({ lang })` once the server accepted it; menus, search bar and badge are rebuilt in the new language. Meanwhile a veil with a spinner covers the canvas, menus included (`.ms-ink-veil`, color `--ms-ink-veil-bg`, shown only past 300 ms), then the menus fade in (class `ms-menu-relabel` on the menu layer, none under `prefers-reduced-motion: reduce`); a refused language puts the select back on the current one
- new: `TranslationsEn`, `TranslationsFr`, types `TTranslationKey`, `TTranslations`, `TTranslationParams`, `TMathDiagnosticSeverity`; option `i18n` on `TModalConfig` and `TChartConfig`
- example: `interactive_canvas_menu_override.html` labels its added items in English, French and German, and overrides a built-in label

## Changes

### Edit menu on several words
- **behaviour** the context menu Edit shows for any selection made of texts only (it used to take one text, and stayed visible with a stale value otherwise); its field is a textarea holding the words in reading order, one line per row. On save each text gets its word back in that order (one undo step); the last text takes any extra words, and texts left without a word are removed (a second undo step)
- **type** `EditContextMenu.editInput` is an `HTMLTextAreaElement`; new `EditContextMenu.isTextSelection`, `distributeWords`, `DOMFactory.textarea`, `buildTextarea`, `TTextareaElConfig`, `BoxOps.groupIntoLines(items, boxOf)`

### Surround gesture decorates the enclosed set
- **behaviour** the surround gesture in Highlight or Surround mode draws one decorator around everything it encloses (one standalone decorator targeting every word and text), instead of one per word or text; a lone text still carries the decorator inside it. Underline and strike-through still decorate word by word
- **behaviour** decorator gestures (surround, underline, strike-through) now decorate strokes recognized as math, one decorator per math block; they were silently skipped
- **behaviour** converting a math block keeps its decorators (`TMath.decorators`), as converting text already did; a decorator spanning several words or blocks is kept on each of them
- **behaviour** undoing a conversion restores the standalone decorators of the converted strokes (they were lost: the conversion's history entry left them out)
- **type** new optional `group` on the `decorator` variant of `TGestureAnnotation`; `SurroundGestureHandler.decorate(ids, decoratorKind)` (protected)

### Decorator context menu on strokes, texts and maths
- **behaviour** the context menu Decorator sets, removes and colors a decorator on every selected stroke, text and math in one undo step (it changed texts only, and was hidden for a lone math stroke): inside each text and math, and as one standalone decorator across the selected strokes lacking it; removing it from strokes shrinks a decorator also on strokes left out of the selection. A locked text or math is refused. A click on the mixed (indeterminate) state now sets it on every symbol; it removed it when the box had been left checked
- **type** `DecoratorContextMenu.symbolsDecorable` returns `TDecorable[]` (`TStroke | TText | TMath`, new); new `decoratorsOf(symbol, kind)`, `setDecorator(kind, enable)`, `setDecoratorColor(kind, color)`; `hasSingleMathSymbol` removed

### UI translations
- **behaviour** `MathDiagnosticMessages` now maps a code to its severity only; read the title and message with `getMathDiagnosticMessage(code, i18n?)`, which takes a `Translator` (English when absent)
- **behaviour** the labels of `SOURCE_TYPE_LABELS`, `DEFAULT_FONT_SIZE_LIST`, `DEFAULT_FONT_WEIGHT_LIST` ("Auto", "Normal", "Bold") and `CanvasThemes.THEMES` are translation keys, shown through `canvas.i18n.t`; a label of your own that is not a key is shown as is
- **type** `CanvasLayer` and `IIMathVariableInputList` constructors take an optional `Translator` last; new `CanvasLayer.veil`, `showVeil(delay?)`, `hideVeil()`

### Narrower action bar
- **behaviour** the Language menu moves from the action bar into the action dropdown, as a labelled sub-menu like Theme or Guide; `LanguageMenuAction` now extends `SubMenuItem`. Its select id becomes `ms-menu-action-language-input` (`ms-menu-action-language` is now the sub-menu wrapper)
- **behaviour** action bar order: Convert, Undo/Redo, then Clear (Clear used to come first)

### Generic symbol type guards
- **type** every symbol type guard is generic over what it is given: `isStroke`, `isRecognizedMath`, `isRecognizedText`, `isStrokeSolverOutput`, `isText`, `isMath`, `isDecorator`, `ShapeUtil.isShape` / `isCircleShape` / `isEllipseShape` / `isPolygonShape`, `EdgeUtil.isEdge` / `isLineEdge` / `isArcEdge` / `isPolyEdge`. They narrow a `TReadonlyDeep<TSymbol>` to the read-only variant (it used to come out mutable), and `symbols.filter(isStroke)` is a `TStroke[]` without a cast. They accept any `{ type: string }`, so a read-only symbol is accepted too; given a `TBaseSymbol` they narrow to `TBaseSymbol & TStroke` as before
- **type** `cloneSymbol<T extends TSymbol>(symbol: T): T` returns the type it was given (it returned `TSymbol`)
- **type** new `TSymbolOfKind<T, TVariant, TTag>` (what a guard narrows to) and `TSymbolTagged`
- **subclass** `IIWriterManager.updateCurrentSymbolShape(shape, pointer)` and `updateCurrentSymbolEdge(edge, pointer)` take the symbol being drawn, already narrowed; new `updateCurrentPolygon(polygon, origin, pointer)`

## Bug Fixes
- fix(export): the text export read every block a stroke belongs to, and a shape (node or edge) has no label: the id its label falls back to, such as `raw-content 31`, was added to the text — and to the session file name taken from its first words. Only text and math blocks are read now
- fix(gesture): the insert gesture on converted text threw `Cannot assign to read only property 'bounds'`: it split the text with the characters of the document's frozen symbol, whose bounds the typesetter writes. It splits a copy now
